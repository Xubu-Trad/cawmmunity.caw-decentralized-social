# Independent execution-client import and proof readback

**Independent full-client import:** Reth v2.10.1 imported all 28 local Geth blocks and transactions from the same complete genesis into its own database. RPC readback returned all 29 matching headers; Reth-generated proofs for 16 registry fields pass the unchanged strict reader. A separate import rejects a corrupted final state root at block28. This extends the earlier Geth/EthereumJS execution comparison to a second full execution client's file-import and readback path. Peer-to-peer synchronization, public-chain authentication and consensus finality remain unverified; no production readiness is claimed.

## Pinned sources and scope

The official [Reth v2.10.1 release](https://github.com/paradigmxyz/reth/releases/tag/v2.10.1) Linux archive matches its GitHub-published SHA-256 `945cfeadc4347e4e024c0605de6436544b876aab389a5f576f3295f8b9b99c12`. The detached release signature was not verified. The host required newer glibc: Ubuntu Noble libc6/libgcc/libstdc++ packages were extracted into an isolated directory, with package digests checked against the official HTTPS package index. No system libraries were replaced; index signatures remain unverified. This limits supply-chain authentication.

The input is the actual captured Shanghai Geth chain, chain ID31337, two synthetic funded accounts and 28 signed transactions. Blocks were serialized to standard RLP without changing their headers; each header hash was checked against the capture before import. Type2 transactions and empty uncles/withdrawals are the fixture's explicit bounds. Reth independently executed and committed the imported history. Its file-import stages replace network acquisition, so this is not a peer-to-peer sync test.

## Reproduction inputs

`evidence/registry-reth-import-20261110/` includes the genesis, RLP bytes encoded as hex text, result and actual Reth RPC proof. Decode the hex to a fresh `blocks.rlp`; use a new empty database for each run:

```sh
reth import --chain genesis.json --datadir fresh-data --db.max-size 512MB --db.growth-step 16MB --db.rocksdb-block-cache-size 32MB --fail-on-invalid-block blocks.rlp
```

Use the pinned release on a compatible runtime. Import exited0, with28blocks and28transactions. Readback was loopback-only, discovery disabled, both inbound/outbound peer limits0, peer count0; the process was stopped afterward. All29 header hashes/state roots match the captured chain. The final eth_getProof response independently generated by Reth passes:

```sh
node --max-old-space-size=256 integration/core-baseline-v1/check-geth-header-proof.mjs evidence/registry-reth-import-20261110/evidence.json evidence/registry-later-20261109/result.json
```

Five proof/header mutations reject. Separately changing only block28's stateRoot to32bytes of0x11 and re-encoding that block causes a fresh Reth import to fail at MerkleExecute: computed root `0x0e5c8a09a836801852924770722afd33969ed8d0f323a4011ac2a9b30d578552` differs from the mutated commitment. Exit1 and the failed lane are preserved. This is one targeted block rejection, not exhaustive adversarial validation.

## Remaining gates

Peer acquisition and synchronization between independent operators; trusted public checkpoint/consensus/finality evidence; broader malformed-body/header and restart/recovery controls; authenticated release toolchains; and a complete automated acquisition/readback package. Existing oversized-transaction reader limits remain unchanged. PR16's deterministic RPC-read comparison gap remains open at its reviewed head; its earlier twelve passing checks do not close that later finding.
