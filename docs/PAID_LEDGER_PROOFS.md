# selected fixed-fixture ledger proofs

FACT -- 18 focused groups pass for a new Node-only experimental ledger decoder. it composes the existing paid-contract/registry code binding with13exact storage witnesses from the selected paid-contract address and header. the compiler layout receipt is pinned by SHA256. nine witnesses cover credits, stakes and nonces for IDs1..3; four cover totalCredits, poolDust, messageCount and entered. zero values require valid absence/zero evidence; missing slots are not treated as zero.

the code first verifies registry state and the paid runtime's immutable binding. it then verifies the complete ledger proof against that same selected address, header and code hash. it checks sum(credits)==totalCredits, stakes<=credits, aggregate liabilities within uint256 and a quiescent entered word of zero. the last condition is an endpoint profile restriction, not proof that reentrancy cannot occur. runtime/registration policy is unchanged; no frontend or recovery adoption path invokes this experiment.

## evidence scope

the Python generator constructs account/storage tries and headers independently of the JavaScript reader using the existing retained fixture primitives. these states are deliberately synthetic: no transaction execution, token funding or real balance observation produced them. valid commitments can be constructed for economically inconsistent states; the four such cases reach and reject at the expected ledger invariant.

| case | result |
| --- | --- |

| nonzero state | credits100/200/300, stakes10/20/30, nonces2/1/0, total600, dust7, messageCount3 decoded |

| missing/duplicate/wrong-key witness, forged credit, cross-state proof | rejects |
| changed address/code, supplied ledger/finality claim, oversized/object input | rejects |

the18groups include the fixture-scope assertion. no claim is made that every constructed state can be reached by executing the contract. all historyMatchesLedger, tokenBackingVerified, withdrawalVerified, executionVerified, accountAuthorityVerified, currentPermissionVerified, consensusVerified, finalityVerified, freshnessVerified and productionAccepted flags remain false. localLedgerInvariantsHold describes only the listed decoded-value checks.
